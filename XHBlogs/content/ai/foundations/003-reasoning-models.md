「先想一下再回答」这句话从提示词技巧变成了产品能力之后，理解成本结构比理解原理更急迫。推理模型的输出账单里有一项是看不见的，而多数人第一次看到账单时都不明白钱花在哪。

## 思维链提示和推理模型不是一回事

思维链（chain of thought，CoT）最早是一种提示技巧：在 few-shot 示例里把解题步骤写出来，引导模型在给答案之前先输出中间推理。它的本质是「用输出 token 换取更多的串行计算」——模型每多生成一个 token，就多一次前向传播，等效于多算了一步。

而原生推理模型是在训练阶段就被教会在回答前生成长段内部推理的模型。用强化学习（reinforcement learning）在可验证的任务上做优化：答案对就给正反馈，答案错就给负反馈，中间怎么想不管。模型于是自己学会了「先列方程、再检查一遍、不行就换思路」这类策略。

区别在控制权。CoT 提示里，你在 prompt 里规定推理格式；推理模型里，推理内容是模型自己决定的，你只能通过接口参数控制思考长度，拿不到完整的思考过程，或者拿到的是摘要。

## 推理 token 为什么贵

推理模型的计费里有一项「推理 token（reasoning tokens）」，按输出价格算，但用户看不见。

以一次中等难度的数学题为例，最终答案可能只有 200 token，推理过程却生成了 3000 token。账单按 3200 输出 token 计，延迟也按 3000 多步的生成时间算。这是很多人第一次用推理模型时最不适应的地方：明明回答很短，却等了三四十秒。

更麻烦的是不确定性。同一个问题，模型这次想 500 token，下次可能想 5000。预算做不准，超时阈值也不好定。

在 API 层面能做的通常只有两件事：设置推理强度的档位（low / medium / high 这类），以及限制最大输出 token 数。后者要小心——如果上限卡得太低，推理会被硬截断，模型没想完就给答案，质量反而比不推理更差。文档分类任务上就常见这种坑：把 `max_tokens` 设成 512 想省成本，结果模型在思考中途被截断，输出全是半截句子。

## 什么任务真的受益

不是所有任务都值得为思考付费。经验上的分界线是这样的：

| 任务类型 | 是否受益 | 原因 |
| --- | --- | --- |
| 多步数值计算 | 明显 | 需要串行展开，无法一次成型 |
| 逻辑约束满足 | 明显 | 需要枚举与排除 |
| 代码调试定位 | 中等 | 依赖上下文里的细节比对 |
| 文本分类 | 很小 | 判断是单步的 |
| 摘要与改写 | 几乎没有 | 没有可推导的中间量 |
| 格式转换 | 负收益 | 思考会引入多余解释 |

判断标准可以简化成一句话：**答案是否依赖一条可以写下来的中间推导链**。如果人可以照着步骤一步步算出来，推理模型大概率能帮上忙；如果人只能凭印象判断，那思考再多也只是在给自己的偏见找理由。

有对照实验能说明这一点：把 200 条客服工单按主题分十类，用推理模型和不推理的模型各跑一遍。准确率差了不到两个百分点，成本差了六倍。这类任务上，思考是纯粹的开销。

## 让推理可见的代价

有些推理模型会把思考过程以摘要形式返回，或者在特定接口下给出完整轨迹。看起来很美好，实际使用要谨慎。

一是长度。完整轨迹可能几万 token，塞回上下文会挤掉真正重要的材料。二是可信度。模型写出来的「因为 A 所以 B」不一定反映它内部真实的计算路径，它是另一个生成任务，同样可能编造。

一般建议把思考轨迹只用于调试，不进生产链路。排查「为什么这次答案不对」时看一眼有用，但不要把它当成可审计的证据。

## 一个具体的用法

在需要可靠输出的场合，可以用推理模型配合结构化输出（structured output），并要求它在推理里做自检：

```json
{
  "reasoning": "先判断题目类型，再列公式，最后代入数值并检查量纲",
  "answer": "…",
  "confidence": 0.0
}
```

schema 里强制三个字段，`reasoning` 只写关键步骤不写废话，`answer` 严格按业务格式，`confidence` 用于下游分流：低于阈值的人工复核。这个结构最大的好处不是提高准确率，而是让失败可分类——是推理方向错了，还是格式没对上，一眼能分。

要注意 `confidence` 是模型的自我报告，校准很差。它说 0.9 的时候真实准确率可能是 0.7。想用它做阈值，得先在标注集上标定一遍，画出可靠性曲线再定切点。

## 成本应该怎么摊

推理模型的单位成本高，但可以换一种算法：比较「单次成本 × 达到目标质量所需的尝试次数」。

不推理的模型在难题上可能要重试三到五次，或者需要人工返工；推理模型一次通过。把返工的人力算进去，很多时候推理模型反而更便宜。反过来，在简单任务上它就是纯粹的浪费。

所以较稳妥的默认策略是分层：先用便宜模型加规则校验跑一遍，把格式不合格、置信度低的样本挑出来，再送推理模型重做。这样大部分流量走低价通道，只有真正难的那部分付费思考。这套结构比单纯换模型更能控制成本，也更稳定。
